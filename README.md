# MiniMe 👧

A tiny animated companion for Android. Instead of a notification, MiniMe slides onto the screen **on top of whatever app is open**, shows a speech bubble with your reminder, waits a few seconds, and slides away.

> Status: first end-to-end prototype. It was written without access to a device or the Flutter SDK, so expect to fix small build/behaviour issues on first run. Android only.

## Features
- Overlay avatar above other apps: slide-in, idle bob, speech bubble, slide-out, draggable, ✕ to dismiss
- Reminders: add / edit / delete / enable, time picker, repeat daily, on chosen days, or every N hours
- Reminders fire via Android `AlarmManager` and work with the Flutter app closed; re-registered after reboot
- Settings: avatar size, message duration, animation duration, sound, quiet hours, overlay position
- Test buttons: **Show MiniMe**, **Test MiniMe Now**, **Test in 5 seconds**

## Setup (one command needs the Flutter SDK)
This folder contains all Dart code, Kotlin code, manifest, and app-level Gradle config. The Gradle wrapper, launcher icons and the remaining Gradle files are generated by *your* Flutter SDK so they match its version. `flutter create` does **not** overwrite existing files.

```bash
cd mini_me
flutter create . --platforms=android --org com.minime --project-name mini_me
flutter pub get
flutter devices
flutter run
```

Requirements: Flutter 3.22+ (Dart 3.4+), Android Studio/SDK with USB debugging enabled on the phone, Android 8.0+ (API 26+).

After `flutter create`, confirm `android/app/src/main/AndroidManifest.xml` still lists `OverlayService` and `android/app/build.gradle.kts` still has `namespace = "com.minime.mini_me"` and `minSdk = 26`.

## How to test
1. Open the app → **Grant Overlay Permission** → enable "Allow display over other apps" → press back. Status turns green.
2. Tap **Test MiniMe Now**: MiniMe slides in, shows "Hi! I'm MiniMe 👋", waits, slides out.
3. Tap **Test in 5 seconds**, press Home and open YouTube. MiniMe appears over it.
4. **Show MiniMe** keeps it on screen until you tap ✕ or **Hide MiniMe**. Drag it anywhere.
5. Allow **Exact alarms** and **Notifications** in the permission card (see below).

## Create a reminder
**Add Reminder** → title, message, time, repeat → Save. For a quick test set the time 2 minutes ahead, leave the switch on, swipe MiniMe out of recents, and wait. Swipe a reminder left to delete it. The two sample reminders start disabled.

## Permissions
| Permission | Why |
|---|---|
| `SYSTEM_ALERT_WINDOW` | Draw the avatar over other apps (user grants in Settings) |
| `FOREGROUND_SERVICE` + `_SPECIAL_USE` | The overlay runs in a short-lived foreground service (required on Android 14+) |
| `POST_NOTIFICATIONS` | Android 13+: shows the service's small status notification |
| `SCHEDULE_EXACT_ALARM` | Android 12+: fire at the exact minute (user grants "Alarms & reminders") |
| `RECEIVE_BOOT_COMPLETED` | Re-register alarms after reboot |

## Architecture
```
Flutter UI → controllers → NativeBridge (MethodChannel "com.minime.mini_me/native")
                                   ↓
MainActivity.kt ──► OverlayService (short-lived foreground service) ──► OverlayManager (WindowManager view)
       │                                                                     └─ Avatar (replaceable), OverlayAnimator
       └──► ReminderScheduler (AlarmManager) ──► AlarmReceiver ──► OverlayService
                 ▲ NativeStore (reminders + settings JSON in SharedPreferences, readable without Flutter)
BootReceiver ──► ReminderScheduler.rescheduleAll
```
Flutter is the source of truth for editing; after each change it pushes reminders and settings to Kotlin, which schedules one alarm per reminder (the next occurrence). When an alarm fires, `AlarmReceiver` schedules the following occurrence, then shows the overlay unless it is quiet hours. Nothing runs in between and nothing polls. The overlay uses native Android views (not a second Flutter engine) for low memory use.

## Android limitations (be aware)
- **Exact alarms** need user approval on Android 12+. Without it, MiniMe falls back to inexact alarms that Android may delay by minutes. Use the "Exact alarms → Allow" row.
- **Battery optimization / OEM skins** (Xiaomi, Oppo, Vivo, Huawei, Samsung "sleeping apps") may block alarms or background overlays. Set battery to "Unrestricted", and on some phones enable autostart / "pop-up while in background".
- **Force-stopping** the app cancels its alarms until you open it again.
- The overlay cannot appear over secure screens (lock screen, some banking apps, system dialogs).
- Starting the overlay from the background is allowed because the app holds overlay permission; if the user revokes it, reminders silently cannot display.
- Reminders pass through a brief foreground service, so a small low-priority notification exists while MiniMe is on screen. Android requires it.
- If the app is not open when you revoke or change a permission, the status updates when you next open it.
